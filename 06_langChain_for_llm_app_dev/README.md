# LangChain for LLM Application Development — Course Examples

This folder holds the coding examples for *LangChain for LLM Application
Development* (DeepLearning.AI / LangChain). The scripts keep the course's
lesson flow, updated to the current LangChain packages (`langchain`,
`langchain-openai`, `langchain-classic`, `langchain-community`,
`langchain-experimental`), one file per lesson. Together they go from a
single chat call to memory, chains, retrieval, evaluation, and tool-using
agents.

- `01_models_prompts_parsers.py` — a direct OpenAI completion, then the same
  style-transfer task through `ChatOpenAI` and `ChatPromptTemplate`. The
  active example extracts `gift`, `delivery_days`, and `price_value` from a
  product review with `StructuredOutputParser` and prints the prompt, the
  raw completion, and the parsed dict.
- `02_memory.py` — conversation memory on a `ConversationChain`. The active
  example is `ConversationSummaryBufferMemory`: it stores a day's schedule,
  asks for a demo idea, and prints the summarized history. Buffer, window,
  and token-buffer demos sit in a triple-quoted block.
- `03_chains.py` — chains over `Data.csv`. The active example is a router
  (`MultiPromptChain`) that sends "What is black body radiation?" to a
  physics prompt. `LLMChain`, `SimpleSequentialChain`, and `SequentialChain`
  (company name, then a review → English → summary → follow-up) are in a
  triple-quoted block.
- `04_qa.py` — question answering over `OutdoorClothingCatalog_1000.csv`.
  Loads each row as a document, embeds it, and runs a `RetrievalQA` chain
  with `chain_type="stuff"` plus `index.query` for shirts with sun
  protection. Answers print as Markdown.
- `05_evaluation.py` — the same catalog Q&A, then an eval set: two
  hand-written examples plus pairs generated by `QAGenerateChain` from the
  first five documents. `QAEvalChain` grades each prediction and prints a
  panel per example.
- `06_agents.py` — a tool-calling agent. The active example registers a
  custom `time` tool and asks for today's date. A math/Wikipedia question
  and a Python REPL sort of a customer list are commented out.
- `Data.csv` — nine product reviews (`Product`, `Review`) read by
  `03_chains.py`.
- `OutdoorClothingCatalog_1000.csv` — clothing catalog (`shirt id`, `name`,
  `description`) embedded by `04_qa.py` and `05_evaluation.py`.

## First-time setup

This folder works with the system Python (here, 3.14). Check your version:

```bash
python3 --version
```

Then:

```bash
cd ~/code/ai-engineer-roadmap/06_langChain_for_llm_app_dev
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### What each step does

**`cd ~/code/ai-engineer-roadmap/06_langChain_for_llm_app_dev`** moves into
the folder that contains the scripts. The environment is created here, next
to the code it is used for.

**`python3 -m venv .venv`** creates a self-contained virtual environment in
`.venv/`, so packages are installed for this project without modifying your
system Python.

**`source .venv/bin/activate`** makes `python` and `pip` point into `.venv/`.
You will usually see `(.venv)` in your prompt.

**`pip install -r requirements.txt`** installs the pinned packages into
`.venv/`:

- `openai==3.57.0` — OpenAI Python client. `01` uses `OpenAI()` and
  `client.chat.completions.create` for the direct-API example.
- `python-dotenv==1.2.4` — loads `OPENAI_API_KEY` from `.env`.
- `langchain==1.5.2` — core framework the other LangChain packages build on.
- `langchain-openai==1.8.5` — `ChatOpenAI` and `OpenAIEmbeddings`.
- `langchain-classic==1.0.8` — chains, memory, output parsers, retrieval
  indexes, and the QA eval chains from the course (`LLMChain`,
  `ConversationChain`, `RetrievalQA`, `QAEvalChain`, and the agent helpers).
- `langchain-community==0.4.2` — `load_tools` for the math and Wikipedia
  tools in `06_agents.py`.
- `langchain-experimental==0.4.2` — `PythonREPLTool` in `06_agents.py`.
- `pandas==3.1.1` — reads `Data.csv` in `03_chains.py`.
- `tiktoken==0.14.0` — token counts for the token-buffer and summary-buffer
  memory classes.
- `rich==15.0.0` — pretty-prints completions, Markdown answers, and eval
  panels.
- `ipython==9.18.1` — `IPython.display.Markdown` in `04_qa.py`. From the
  terminal, `display()` reprints that Markdown with Rich.
- `wikipedia==1.4.0` — lookup backend for the Wikipedia tool.
- `numexpr==2.14.2` — expression evaluator used by the `llm-math` tool.
- `panel==1.10.0`, `greenlet==3.5.6`, and `mypy-extensions==1.2.0` — pinned
  with the rest of this environment (Panel widgets, greenlet, and typing
  helpers the LangChain stack expects).

`requirements.txt` is the Python equivalent of `package.json` in a Node
project: it records the exact versions this folder needs, so the environment can
be recreated elsewhere.

> `os`, `csv`, `datetime`, and `warnings` are part of Python's standard
> library, so they are **not** installed with `pip`. Importing them always
> works.

## Credentials: keep them secret

The scripts read one environment variable:

- `OPENAI_API_KEY`

This is a **critical secret**. It can be used to call OpenAI and bill your
account, so it must never be committed, pasted into chat, or shared.

It lives in a single `.env` file at the **repository root**. Create or edit it:

```bash
cd ~/code/ai-engineer-roadmap
nano .env
```

Add this line (alongside any other keys this repo already uses):

```dotenv
OPENAI_API_KEY=your-secret-key
```

Rules for this file:

- `.env` is listed in the repository-root `.gitignore`, so Git ignores it.
- There is no committed template: never put real keys in a tracked file.
- If you ever commit a key by accident, rotate it immediately in OpenAI.
- The scripts load `.env` with `load_dotenv(find_dotenv())`, which walks up
  from the current working directory. Run them from this folder or
  elsewhere inside the repository so they can find the root `.env`.

## Running the scripts

Every time you open a **new terminal**, activate the environment first:

```bash
cd ~/code/ai-engineer-roadmap/06_langChain_for_llm_app_dev
source .venv/bin/activate

python 01_models_prompts_parsers.py
python 02_memory.py
python 03_chains.py
python 04_qa.py
python 05_evaluation.py
python 06_agents.py
```

By default each file runs its last uncommented example; earlier ones sit in a
triple-quoted block or behind `#`. Uncomment one block at a time if you want
to replay a specific prompt.

`01_models_prompts_parsers.py` makes one chat call and prints the extraction
prompt, the model's text, and (after `parser.parse`) a dict. The last three
lines (`output_dict`, `type(...)`, `output_dict.get(...)`) only show a value
when you run the file in a notebook or REPL; from the terminal, look at the
`print` calls above them.

`02_memory.py` calls the model while it summarizes saved turns, then once
more for "What would be a good demo to show?". `verbose=True` prints the
filled prompt, including the current history.

`03_chains.py` reads `Data.csv` with a relative path, so run it from this
folder. The active router makes two calls (pick a destination, then answer).
The review chain inside the triple-quoted block uses `df.Review[5]`.

`04_qa.py` and `05_evaluation.py` embed `OutdoorClothingCatalog_1000.csv`
(about a thousand products) on every run, then call the chat model. They
take longer and cost more than `01`–`03`. Both scripts open the CSV with a
relative path, so run them from this folder. `05_evaluation.py` also
generates question–answer pairs for the first five documents and grades
every example, so it makes many sequential API calls. `set_debug(True)` in
the middle of `05` is turned off again before the graded run.

`06_agents.py` builds math, Wikipedia, and Python REPL tools, then the
active path calls only the custom date tool ("whats the date today?").
`verbose=True` prints each tool call. A broad `except` prints
`exception on external access` if that call fails.

You can tell the environment is active because `(.venv)` appears at the start of
your prompt. To check which Python is being used:

```bash
which python
```

It should print a path inside `06_langChain_for_llm_app_dev/.venv/bin/`.

`__pycache__/` is created by Python when it compiles a local module. You do
not create it by hand. Running these files as the main program often does
not write a cache for that file; that is normal. Deleting `__pycache__/` is
safe. Python regenerates it when needed.

environment or uninstall anything, so you can activate it again later.

## Virtual environment rules

- A virtual environment contains **absolute paths**. It cannot be moved or
  renamed. If it is in the wrong folder, delete it and create it again.
- Only one environment can be active in a terminal at a time. Run `deactivate`
  before activating a different one.
- Activation is per terminal. A new terminal starts with the system Python, so
  activate the environment again.

## Course notes that differ from the original notebooks

The notebooks used `langchain.chat_models.ChatOpenAI`, `langchain.chains`,
`langchain.memory`, `model="gpt-3.5-turbo"`, and `temperature=0`. This folder
splits those imports across `langchain_openai`, `langchain_classic`,
`langchain_core`, `langchain_community`, and `langchain_experimental`. After
2024-06-12 the scripts set `llm_model` to `gpt-5-nano` (`gpt-4o-mini` in
`06_agents.py`) and pass `temperature=1`, which is the only temperature
`gpt-5-nano` accepts. Chat models are called with `chat.invoke(messages)`
and `response.content`.

Retrieval uses `InMemoryVectorStore` and a small local `CSVLoader` (one
`Document` per CSV row). The notebooks used `DocArrayInMemorySearch` and
`langchain.document_loaders.CSVLoader`.

`05_evaluation.py` replaces the default `QAGenerateChain` parser. Newer
models often put a newline after `ANSWER:`; the regex here accepts that.

`06_agents.py` keeps the names `initialize_agent` and `create_python_agent`,
but both build a native tool-calling agent (`create_tool_calling_agent`).
The classic ReAct agents send `stop` sequences, which these models reject.
A `ChatOpenAI` subclass drops `stop` if a caller still passes it.

## Troubleshooting

- `ModuleNotFoundError: No module named 'langchain'` / `'langchain_openai'` /
  `'langchain_classic'` / `'langchain_community'` /
  `'langchain_experimental'`: the environment is not activated, or the
  packages were installed elsewhere. Activate it and run
  `pip install -r requirements.txt`.
- `ModuleNotFoundError: No module named 'dotenv'`: install with
  `pip install python-dotenv` inside the activated environment, or
  `pip install -r requirements.txt`.
- `ModuleNotFoundError: No module named 'openai'` / `'pandas'` / `'rich'` /
  `'IPython'` / `'tiktoken'`: install with `pip install -r requirements.txt`
  inside the activated environment.
- `FileNotFoundError` for `Data.csv` or `OutdoorClothingCatalog_1000.csv`:
  `03`, `04`, and `05` open those files with a relative path. `cd` into this
  folder before running them.
- `BadRequestError: 'temperature' does not support 0 with this model`
  (or a value other than `1`): `gpt-5-nano` rejects non-default temperature.
  Leave the call at `temperature=1`.
- `BadRequestError` mentioning `stop`: a classic ReAct agent
  (`CHAT_ZERO_SHOT_REACT_DESCRIPTION` or the stock `create_python_agent`)
  was used with this model. Use the helpers at the top of `06_agents.py`.
- `OutputParserException` from `QAGenerateChain`: the model did not emit
  `QUESTION:` / `ANSWER:`. The regex in `05_evaluation.py` already allows a
  newline after `ANSWER:`; retry the run.
- `BadRequestError` / `AuthenticationError` / `401`: `OPENAI_API_KEY` is
  missing, empty, or wrong in the root `.env`.
- Completions never print and there is no traceback: `find_dotenv()` did not
  find the root `.env`. `cd` into this folder (or the repo) and run again.
- `06_agents.py` prints `exception on external access`: the date-tool call
  failed. Read the traceback by narrowing the `except` if you need the
  underlying error. Wikipedia and math examples need a network call when
  you uncomment them.

## Managing dependencies

`requirements.txt` in this folder lists the packages this example needs, pinned
to exact versions. It plays the same role as `package.json` in a Node project:
it is the record of what must be installed.

To install (or reinstall) everything into an activated environment:

```bash
cd ~/code/ai-engineer-roadmap/06_langChain_for_llm_app_dev
source .venv/bin/activate
pip install -r requirements.txt
```

If you add a package you intend to keep, add its pinned version to
`requirements.txt` by hand. Prefer a short list of **direct** imports
(`openai`, `python-dotenv`, `langchain`, `langchain-openai`,
`langchain-classic`, `langchain-community`, `langchain-experimental`,
`pandas`, `tiktoken`, `rich`, `ipython`, `wikipedia`, `numexpr`) over
`pip freeze`, which also dumps transitive packages.
